安装与使用
  1. 备份、抹盘并重装 macOS

    先备份数据。关机后长按电源键，进入「选项 → 继续」。用磁盘工具核对目标后抹掉宗卷组，再重新安装 macOS；抹盘会删除目标安装中的文件和账户。

  2. 安装后返回恢复模式

    安装完成后再次进入恢复模式，挂载或解锁目标系统卷及同组数据卷，打开「实用工具 → 终端」并连接网络。

  3. 复制命令，按提示操作

    优先选择国内地址。脚本自动匹配同组卷，创建临时账户 apple / 1234 并完成配置，无需输入或二次确认；仅检查请加 --check。

  4. 确认结果，再重启登录

    看到完成提示后，重启并用 apple / 1234 登录。先创建并登录验证自己的管理员，再删除临时账户，之后再按后续说明处理 SIP。

登录后的后续操作

先登录临时账户，创建并验证自己的管理员，再删除临时账户。接着关闭 SIP、按下文处理配置标记和注册服务、补齐 hosts 扩展屏蔽列表，完成后恢复 SIP。当前脚本已在离线数据卷处理四个配置标记，并添加三个默认注册域名；下文还包括禁用注册服务和补齐六域名名单的步骤。

1. 关闭 SIP 前：先替换临时管理员账号

先创建并验证自己的管理员，再删除临时 apple；不要先删除唯一可用账号。

  1. 用 apple / 1234 登录；如临时账户中已有文件，先备份。
  2. 打开“系统设置”→“用户与群组”→“添加用户”，按提示验证，账户类型选择“管理员”，创建自己的全新账号和密码，不要仅重命名 apple。
  3. 从苹果菜单退出登录，使用新账号登录，确认密码可用且显示为管理员；准备修改 SIP 时，先按下方只读命令核对新账号的 Token 和卷所有权授权，再删除临时账号。
  4. 使用新管理员进入“用户与群组”，选择临时 apple，点击“删除用户”。按需要保留或删除其个人文件夹；先确认所需文件已备份。不要在仍登录 apple 时删除它，也不要用 rm 或 dscl 强制删除唯一管理员。
  5. 后续恢复模式的身份验证使用新管理员账号。完成账号替换后，再按第 2 节关闭 SIP。

如果 csrutil disable 提示 no admin user，不要把“删掉再新建账号”当作必然修复。管理员身份、Secure Token 和 Apple 芯片 Mac 的卷所有权是不同条件；修改启动安全策略涉及管理员及卷所有权。可在新账号的系统终端做以下只读检查：

sysadminctl -secureTokenStatus "$(id -un)"
dscl . -read "/Users/$(id -un)" GeneratedUID
sudo diskutil apfs listUsers /

核对当前账号的 Token 状态，以及其 GUID 对应的卷所有权。如果授权不满足，先按 Apple 流程处理，保留可用账号，不要反复删建或继续关闭 SIP。参考 Apple：添加用户、删除用户及 Secure Token 与卷所有权。

2. 手动修复前：先关闭 SIP

按本节在已启动的系统中进行后续配置前，先按以下步骤关闭 SIP；已经显示 disabled 时可跳过关闭步骤。

  1. 将 Mac 关机，长按电源键进入启动选项，选择“选项”→“继续”。
  2. 在恢复模式打开“实用工具”→“终端”，执行：
csrutil disable
  1. 按屏幕提示完成确认或用户验证，然后通过苹果菜单重新启动，登录 macOS。
  2. 在系统终端执行以下命令，确认显示 disabled，再继续手动修复：
csrutil status

csrutil disable 在恢复模式中执行；csrutil status 可在系统终端检查。脚本不会代你切换 SIP。后续操作完成后，按第 5 节重新开启 SIP。操作方式参考 Apple：配置 SIP。

3. 核对或修复配置标记

先按第 2 节关闭 SIP 并登录系统，在系统终端依次执行下面 5 条命令。sudo 会要求输入当前管理员密码，输入时不显示字符：

sudo rm /var/db/ConfigurationProfiles/Settings/.cloudConfigHasActivationRecord
sudo rm /var/db/ConfigurationProfiles/Settings/.cloudConfigRecordFound
sudo touch /var/db/ConfigurationProfiles/Settings/.cloudConfigProfileInstalled
sudo touch /var/db/ConfigurationProfiles/Settings/.cloudConfigRecordNotFound
sudo launchctl disable system/com.apple.ManagedClient.enroll

执行命令检查结果：

sudo profiles show -type enrollment

可能出现类似错误：

Error fetching Device Enrollment configuration: (34000) Error Domain=MCCloudConfigurationErrorDomain Code=34000 "The device failed to request configuration from the cloud." UserInfo={NSLocalizedDescription=The device failed to request configuration from the cloud., CloudConfigurationErrorType=CloudConfigurationFatalError}

该提示表示本次未能从云端获取设备注册配置。网络屏蔽等情况也可能导致请求失败，不能仅凭错误码 34000 判断已解除监管或组织端设备归属；组织端释放需由有权限的管理员操作，参见 Apple：释放设备。完成后继续第 4 节，最后按第 5 节恢复 SIP。

4. 编辑 hosts 扩展屏蔽列表

默认脚本已经添加 iprofiles.apple.com、mdmenrollment.apple.com、deviceenrollment.apple.com。扩展名单含有其他用途的 Apple 服务；按 Apple 联网清单，需要区分以下用途：

域名 用途及影响
iprofiles.apple.com、mdmenrollment.apple.com、deviceenrollment.apple.com 设备注册相关，已包含在默认脚本中
gdmf.apple.com 软件更新目录及受管理更新查询；屏蔽可能影响系统更新检查
albert.apple.com 设备激活；屏蔽可能影响正常激活
acmdm.apple.com 扩展项；本次所查官方清单中未确认其具体用途

接着补齐下面的六域名名单。先备份 hosts，再以管理员权限打开编辑器：

sudo cp -p /etc/hosts "/etc/hosts.before-mdm-$(date +%Y%m%d-%H%M%S)" &&
sudo vi /etc/hosts

切换到英文输入法，先按 Esc，再按 G 到最后一行，按小写 o 新建末尾空行并进入编辑状态。仅添加尚未存在的条目，保留原有内容：

0.0.0.0 iprofiles.apple.com
0.0.0.0 mdmenrollment.apple.com
0.0.0.0 deviceenrollment.apple.com
0.0.0.0 gdmf.apple.com
0.0.0.0 acmdm.apple.com
0.0.0.0 albert.apple.com

按 Esc，输入 :wq 并回车保存退出；不保存退出可用 :q!。需要刷新 DNS 缓存时执行：

sudo dscacheutil -flushcache
sudo killall -HUP mDNSResponder

这份名单与 --domains xiaohu-six 不同，后者包含 deviceservices-external.apple.com，不包含 gdmf.apple.com。本节仅提供手动操作说明，不改变脚本的默认域名选项。若新增屏蔽后出现更新检查或激活异常，先删除本次新增的相关条目或使用备份恢复，再重试。保留备份并在 OTA 后核对实际状态，不将这些设置视为“以后绝不会再提示”的保证。

5. 恢复开启 SIP

若之前关闭过 SIP，完成所需操作后建议恢复开启；如果 csrutil status 已显示 enabled，保持现状即可。

  1. 关机，长按电源键进入启动选项，选择“选项”→“继续”。
  2. 在恢复模式中打开“实用工具”→“终端”，执行：
csrutil enable
  1. 按屏幕提示完成验证，再通过苹果菜单重新启动 Mac。
  2. 登录系统后再次执行 csrutil status，确认显示 enabled。

若 App Store 下载的 iPhone/iPad 应用提示启动安全策略不满足，先恢复 SIP，并按应用或系统提示检查启动安全策略；不能仅凭应用打不开就判断是 SIP 导致。命令及重启要求可参考 Apple：配置 SIP。

Sign in with the temporary account, create and verify your own administrator, then remove the temporary account. Next, disable SIP, follow the configuration-marker and enrollment-service steps below, complete the extended hosts blocklist, and re-enable SIP. The script already handles four configuration markers on the offline Data volume and adds three enrollment hosts; the steps below also disable the enrollment service and complete the six-host list.

1. Before changing SIP: replace the temporary administrator

Create and verify your own administrator before removing temporary account apple. Do not delete your only usable account first.

  1. Sign in with apple / 1234 and back up any files stored in that account.
  2. Open System Settings → Users & Groups → Add User, authenticate as requested, choose Administrator, and create a new personal account and password. Do not merely rename apple.
  3. Log out from the Apple menu and sign in with the new account. Verify its password and Administrator role, then check the token and volume-owner authorization described below before removing the temporary account.
  4. While signed in as the new administrator, select temporary account apple in Users & Groups and choose Delete User. Keep or delete its home folder as appropriate after backing up needed files. Do not delete the account while signed in to it or force-remove your only administrator with rm or dscl.
  5. Use the new administrator for Recovery authentication, then proceed to SIP changes in section 2.

If csrutil disable reports no admin user, deleting and recreating accounts is not a guaranteed fix. Administrator membership, Secure Token, and Apple silicon volume ownership are distinct; startup security changes involve administrator and owner authorization. Run these read-only checks in the new account's system Terminal:

sysadminctl -secureTokenStatus "$(id -un)"
dscl . -read "/Users/$(id -un)" GeneratedUID
sudo diskutil apfs listUsers /

Check the current account's token state and the ownership associated with its GUID. Resolve missing authorization through Apple's documented procedures before further SIP changes; retain usable accounts instead of repeatedly deleting and recreating them. See Apple's guides for adding users, deleting users, and tokens and volume ownership.

2. Before manual repair: disable SIP

Before performing the following configuration steps in the booted system, disable SIP using these steps. Skip the disabling step if it already reports disabled.

  1. Shut down, hold the power button for startup options, and choose Options → Continue.
  2. In Recovery, open Utilities → Terminal and run:
csrutil disable
  1. Complete the requested confirmation or authentication, then restart from the Apple menu and sign in to macOS.
  2. In the normal system Terminal, run the following and confirm that it reports disabled before continuing:
csrutil status

Run csrutil disable in Recovery; csrutil status can check the state in the normal system. The script does not switch SIP for you. Re-enable it in section 5 after completing the work. See Apple's SIP configuration guide.

3. Inspect or repair configuration markers

Disable SIP and sign in as described in section 2, then run these five commands in order in the normal system Terminal. sudo asks for your current administrator password; typed characters remain hidden:

sudo rm /var/db/ConfigurationProfiles/Settings/.cloudConfigHasActivationRecord
sudo rm /var/db/ConfigurationProfiles/Settings/.cloudConfigRecordFound
sudo touch /var/db/ConfigurationProfiles/Settings/.cloudConfigProfileInstalled
sudo touch /var/db/ConfigurationProfiles/Settings/.cloudConfigRecordNotFound
sudo launchctl disable system/com.apple.ManagedClient.enroll

Run this command to check the result:

sudo profiles show -type enrollment

You may see an error similar to:

Error fetching Device Enrollment configuration: (34000) Error Domain=MCCloudConfigurationErrorDomain Code=34000 "The device failed to request configuration from the cloud." UserInfo={NSLocalizedDescription=The device failed to request configuration from the cloud., CloudConfigurationErrorType=CloudConfigurationFatalError}

This message means the current request could not fetch the device enrollment configuration from the cloud. Network blocking can also cause request failures, so error 34000 alone does not prove that management or organization-side ownership has been removed. Organization-side release requires an authorized administrator; see Apple: Release devices. Continue with section 4, then re-enable SIP in section 5.

4. Extend the hosts blocklist

The default script already adds iprofiles.apple.com, mdmenrollment.apple.com, and deviceenrollment.apple.com. The extended list includes Apple services with other purposes. See Apple's network requirements:

Host Purpose and effect
iprofiles.apple.com, mdmenrollment.apple.com, deviceenrollment.apple.com Enrollment services, already included by default
gdmf.apple.com Update catalogs and managed-update queries; blocking may affect update checks
albert.apple.com Device activation; blocking may affect activation
acmdm.apple.com Additional host; its specific purpose was not confirmed in the official list reviewed

Next, complete the following six-host list. Back up hosts and open the editor with administrator privileges:

sudo cp -p /etc/hosts "/etc/hosts.before-mdm-$(date +%Y%m%d-%H%M%S)" &&
sudo vi /etc/hosts

Use an English input method. Press Esc, then G to reach the last line, then lowercase o to open a new line at the end in insert mode. Preserve existing content and add only entries that are not already present:

0.0.0.0 iprofiles.apple.com
0.0.0.0 mdmenrollment.apple.com
0.0.0.0 deviceenrollment.apple.com
0.0.0.0 gdmf.apple.com
0.0.0.0 acmdm.apple.com
0.0.0.0 albert.apple.com

Press Esc, type :wq, and press Return to save and exit. Use :q! to exit without saving. To refresh DNS caches if needed:

sudo dscacheutil -flushcache
sudo killall -HUP mDNSResponder

This list differs from --domains xiaohu-six, which includes deviceservices-external.apple.com and excludes gdmf.apple.com. These are manual instructions; the script's default host selection stays the same. If added blocks cause update-check or activation issues, remove the relevant new entries or restore your backup before retrying. Keep backups and review the actual state after OTA updates; these settings do not guarantee that prompts will never return.

5. Re-enable SIP

If you previously disabled SIP, restore it after completing the necessary work. If csrutil status already reports enabled, leave it enabled.

  1. Shut down, hold the power button for startup options, and choose Options → Continue.
  2. In Recovery, open Utilities → Terminal and run:
csrutil enable
  1. Complete the requested authentication and restart from the Apple menu.
  2. After signing in, run csrutil status again and confirm that it reports enabled.

If an iPhone/iPad app from the App Store reports an incompatible startup security policy, restore SIP and follow the app or system guidance for startup security settings. An app failing to open is not, by itself, proof of a SIP issue. See Apple's SIP configuration guide for the commands and restart requirement.
